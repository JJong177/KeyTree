# 剪贴板账号识别

## 使用

在 Windows 桌面版的 **设置 → 便利** 中开启 **回到软件时识别剪贴板账号**，默认关闭。

从网页、Excel 或 TXT 复制包含账号信息的一段文本，再切回已经解锁的 KeyTree 主窗口。识别成功后先显示预览，密码默认遮挡；点击“填入新增页”只预填草稿。请核对、补充标题和网址，最后手动点击新增页的“保存”。忽略或放弃草稿不会创建条目。

正在编辑条目、打开设置、使用快速面板或锁库过程中不读取；关闭这些界面后，下一次切回主窗口才尝试识别。应用解锁本身不触发读取。

## 支持的内容

- 带表头的 CSV 或制表符表格，例如 `name,url,username,password`，以及“标题、网址、账号、密码”等中文表头。
- 带明确字段标签的多行文本，例如“账号：…”、“密码：…”、“网址：…”。分隔符后的密码按原字符保留，包括首尾空格；多余说明不会被猜作密码。
- 剪贴板附带的 HTML 表格：解析明确表头或两列的字段/值结构。合并单元格、重复字段等歧义结构不自动猜列。
- 最多预览 50 条表格记录，每次选择一条填入新增页；不批量自动保存。

无表头的两段文字或单独一个无标签字符串不会被强行认作账号、密码。建议连同字段标签或表头一起复制。

## 来源与隐私

- 仅在切回已解锁且处于前台的主窗口时读取当前剪贴板，不后台监听、不读取剪贴板历史、不上传、不记录原文或持久保存识别候选。
- 识别功能只读，不清空、不替换外部程序复制的内容。原有 KeyTree 安全复制和定时清理逻辑不变。
- 某些网页复制会带来源 URL，只展示其站点来源，不展示路径、查询参数或片段。剪贴板所属应用名为尽力获取，可能是中转程序；两者均不作为可信来源认证。
- **复制来源不等于账号登录网址**，因此不会用来源自动补条目的网址。来源缺失时显示“未知”。
- 忽略、失焦、关闭开关、锁库或组件销毁会丢弃识别预览并使异步结果失效；已确认填入新增页的字段按普通未保存草稿处理。
- 同一剪贴板版本不会在本次已解锁窗口生命周期中反复提示。只识别最后一份内容，不能自动拼接先复制账号、再复制密码的两次操作。
- 第一版不含浏览器扩展，不扫描网页中的未复制字段，不绕过 Chrome/Edge 内置页面的访问限制。

## 开发验证

从 `keytree` 目录运行：

```powershell
npm test
npm run build
cargo test --manifest-path .\src-tauri\Cargo.toml --lib
cargo check --manifest-path .\src-tauri\Cargo.toml --target x86_64-pc-windows-msvc
```

浏览器冒烟测试需先启动开发服务器，另开终端运行：

```powershell
npm run dev -- --port 1427
npm run test:clipboard-browser
```

浏览器测试使用 Node 内置 CDP/WebSocket 与独立临时 Edge 配置，不安装测试依赖、不访问系统剪贴板或真实密码库。可通过 `KEYTREE_TEST_BROWSER` 指定 Chromium 系浏览器可执行路径，`KEYTREE_TEST_URL` 指定开发服务器地址。

自动化覆盖字段字符保持、来源与登录网址分离、HTML 不执行、预览密码遮挡、手动确认/保存、编辑防覆盖及锁库异步失效。真实 Windows 桌面切换、不同应用的剪贴板兼容性仍需桌面人工验收。

# WebDAV 手动同步（首版）

> 已启用通用 WebDAV 手动同步及坚果云裸 ETag 兼容。坚果云先手动上传同一份 KDBX，再配置已有文件地址；分享链接不能直接使用。真实账号和手机联调尚未验收。

KeyTree 保留本地 KDBX，手动与 WebDAV 上的同一份库同步。Android/iPhone 使用支持 KDBX 和相应 WebDAV 服务的 KeePass 兼容应用；KeyTree 本身不提供手机版。

## 开始使用

1. 先备份当前库，在 Windows 打开要同步的本地 KDBX。不要把它同时放在云盘客户端的同步目录中，否则会形成两套同步机制。
2. 在“设置 → 同步”填写完整的 **HTTPS `.kdbx` 文件地址**、用户名和服务提供的应用专用密码，点击“保存配置”。地址不能包含账号密码、查询参数或片段；上级目录必须已存在。
3. “测试连接（只读）”只读取远端，检查 KDBX 文件头，并分别显示标准强 ETag、坚果云兼容版本标识、未返回、弱值或格式异常；不会解密、合并或上传。返回网页等非 KDBX 内容时会报告文件验证失败。“可读取文件头”不代表可安全上传，也不代表两端内容一致；可用版本标识只是必要条件，实际条件写入在同步时确认。
4. 点击“立即同步”。一般 WebDAV 服务首次远端尚无文件时，核对地址并明确勾选“允许首次创建”，再执行同步。**坚果云例外：不执行首次创建，先在网页或客户端手动上传当前同一份 KDBX**，再通过 KeyTree 条件更新；不可用独立新建库代替。
5. 手机端打开同一远端 KDBX，使用相同主密码及密钥文件。每次换设备编辑前先同步，编辑完再同步；Windows 首版不定时自动同步。

新 Windows 设备应先从 WebDAV 下载这份 KDBX，再在 KeyTree 中打开并配置同步。独立新建的库即使密码相同，也不是同一份库，不能强行合并。

## 坚果云填写示例

在坚果云安全设置的第三方应用管理中，为 KeyTree 生成应用密码。授权信息只在 KeyTree 内填写，不要通过聊天发送。

- 用户名：坚果云账号（通常为邮箱）。
- 密码：第三方应用专用密码，不是坚果云登录密码。
- 服务根地址：`https://dav.jianguoyun.com/dav/`；KeyTree 要求的是**完整文件地址**，例如 `https://dav.jianguoyun.com/dav/KeyTree/vault.kdbx`。将示例路径替换为实际目录和文件名，先在坚果云中创建上级目录。

`www.jianguoyun.com/c/sd/…` 是网页分享地址，不能粘贴为 WebDAV 地址，也不能从分享编号推导出你的私有 WebDAV 路径。若库在他人分享中，应先获得授权并下载同一份 KDBX，再按你有权限访问的实际 WebDAV 路径配置。

保存后先进行只读测试。若返回缺失，先核对路径；一般 WebDAV 服务只有确实要上传当前库作为新远端时才勾选首次创建；坚果云不提供此操作。若没有可用的版本标识或条件请求支持，会停止同步，不能跳过保护。服务授权、配额/套餐及实际兼容性以该账户和服务现状为准。

## 同步如何保护数据

顺序为：确认本地保存 → 读取远端 → 用当前凭据验证同一库及公开元数据 → 合并条目与历史备注 → 成功保存到本地 → 条件上传本地密文。

- 一般服务的已有远端文件必须有有效的强 ETag，上传带 `If-Match`；首次创建带 `If-None-Match: *`。坚果云已有文件允许下述受限裸 ETag 兼容，但不依赖其首次创建条件。不支持安全条件更新时停止，不降级为无条件覆盖。
- 收到 412 表示远端已变化，本次不覆盖。保留本地已合并的内容，重新点击同步以读取最新版本。
- 网络、授权或服务器错误不会使本地库不可用。本地保存失败时不上传；有未保存修改时应重试保存或另存 KDBX。
- 远端不是同一库、无法用当前凭据解密，或两端公开提示等公开元数据不同，会停止自动合并与上传。先分别备份、核对正确文件和凭据，不要靠覆盖解决。
- 锁定或切库取消后续处理；已经发出的密文 HTTP 请求无法撤回。若上传响应丢失，服务端可能已收到文件，应重新同步确认，不要把错误视为“服务器肯定没改”。
- 界面区分本地保存、未检查远端、本次上传确认和仍有修改待同步。“上次上传确认”只是历史时间，不保证远端此刻没有新修改。

## 凭据和限制

- 本机 WebDAV 配置由 Windows DPAPI 加密保存；授权密码不回传给界面，不写入浏览器存储或 KDBX。修改服务来源或用户名必须重新填写密码；同来源同用户名可留空保留。
- “忘记本机配置”需要确认，只删除本机授权与配置，不删除本地库或远端文件。
- 仅接受 HTTPS，正常校验证书，不跟随重定向；连接超时 10 秒，请求整体超时 30 秒，库文件上限 64 MiB。
- 不同步密钥文件、Windows Hello 缓存、应用设置或审计记录。密钥文件需通过独立安全途径交给其他设备，丢失后不能绕过。
- KDBX 主体加密，**公开主密码提示仍为明文**，会随文件上传；不要在提示中放敏感信息。
- 历史备注写在加密自定义元数据中，但其他客户端是否保留它、删除历史能否跨客户端保持，取决于对方实现；不承诺永久擦除云端历史或旧备份。
- 首版没有远端浏览、自动下载引导、后台同步、自动冲突覆盖或各家云盘私有 API。

## ETag 提示如何排查

正确地址仍出现 ETag 提示时，重新点“测试连接（只读）”并查看具体分类。不需要反复重填密码，也不要为了绕过错误勾选首次创建。缺失、弱值和任意异常格式不能用于现有文件的安全条件上传；坚果云仅允许下述已知裸标识格式。KeyTree 不会给值补引号、将弱值当强值，或退回无条件覆盖。诊断只返回分类，不显示原始响应头、授权信息或文件正文。若真实服务仅提供这些响应，当前同步方案会安全停止；这不表示本地库损坏，也不能单凭旧的统一错误判断所有坚果云账户都不支持。

## 坚果云裸 ETag 兼容边界

坚果云可能返回未加双引号的版本标识，要求 `If-Match` 按原值回传。此前标准强 ETag 解析器会拒绝它，导致文件可读却不能同步。当前只在 HTTPS、主机精确为 `dav.jianguoyun.com`、443 端口且路径在 `/dav/` 下启用兼容：

- 只接受单个、有界、HTTP token 形态的不透明标识；不接受通配符、弱前缀、列表、重复 ETag、空白或引号异常。不从正文哈希、校验和或其他响应头制造版本标识。
- 原生票据保留 GET 对应的标识，`If-Match` 原样发送，不加引号。收到 412 仍停止，用户重新 GET/合并；不撤掉条件盲重试。
- GET 显式请求 `Accept-Encoding: identity`，避免压缩响应改变校验标识。连接测试仍为只读，不声称已验证条件 PUT，也不显示原始版本值或授权信息。
- 公开实测记录报告坚果云可能忽略 `If-None-Match: *`。因此 KeyTree 在准备与发送边界均阻止坚果云首次创建；界面隐藏对应勾选，要求先手动上传同一份 KDBX。已有文件的原样 `If-Match` 更新不受影响。

依据：开发中读取了以下公开项目的源码与实测报告，**不是本项目对用户真实账号的验证，也不照搬其中的无条件降级**：

- [Contrail #34：裸 ETag 原样转发，匹配更新成功、过期返回 412](https://github.com/MingweiYan/Contrail/pull/34)，源码提交 `270ebcc679f7dacc0eec3009ebf12e3f7fd4f2cc`。
- [Agentero #567：坚果云 GET 裸 ETag、If-Match 生效、If-None-Match 被忽略的记录](https://github.com/poco-ai/Agentero/pull/567)。KeyTree 不采用其无条件上传或 fail-open 降级。
